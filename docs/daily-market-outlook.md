# Daily market outlook

The Persian **چشم‌انداز روزانه** dashboard tab explains conditional 3–7 day scenarios. It is independent of hourly entry signals and never creates orders or proposed setups. It is not a months-long investment forecast or a promise of a future price path.

## Operation

- Automatic generation is off by default. An administrator can enable it and choose a Tehran-local time (default 08:05). The scheduler checks each minute; delivery follows data collection and AI completion.
- A manual generation button uses the same daily allowance. There is at most one attempt per symbol/Tehran calendar date, enforced by a database unique constraint. Failures also consume that day's attempt; there is no automatic paid retry.
- If another analysis holds the shared lock, the scheduled job tries again on subsequent ticks without consuming the daily allowance. A report can therefore arrive later than its configured start time.
- The existing AI connection/model selection is reused. API connections incur additional inference usage; token counts are stored with each report. No real paid request was made during development.
- Running work has a 15-minute total deadline and a 30-minute shared lock lease. Interrupted rows are marked failed after 32 minutes; a restart does not re-run an interrupted day's inference.
- An old completed report remains visible when today's attempt fails, with its own date and an explicit stale warning. The archive exposes the latest 30 attempts for the configured symbol.

## Data and output

Fetch 90 days of Bitunix 4h candles; aggregate only complete UTC days and complete Monday-start weeks. Require contiguous recent data and a fresh quote before inference. Supply 80 daily bars, up to 12 completed weeks and 120 4h bars. Optional source-labelled market intelligence is supplementary. No news or economic-calendar feed is connected.

The validated report includes weekly/daily structure, dominant and alternative scenarios, activation/invalidation conditions, two to four conditional stages, referenced target levels, uncertainty, what to monitor, and changes from the prior completed report. Level IDs must reference deterministic levels from the supplied data. Narrative claims are generated by the model and are not independently proven by schema validation.

The chart shows historical daily closes only. No fabricated future candle path, win-rate percentage or target-arrival date is displayed.

## Upgrade and production compatibility

Startup creates two additive tables (`daily_outlook_settings`, `daily_outlook_runs`) through the existing SQLAlchemy initialization. Back up the database and retain a copy of local production diffs before deploying. No production deployment is performed by this change.

This branch also preserves the three manually applied production fixes reported in the support session: market context reads from `_artifacts`; terminal setups no longer block same-direction proposals; regular hourly analysis aligns to fixed UTC interval boundaries plus one minute and successful manual runs do not move that schedule. The corresponding old completion-relative scheduler assertion is updated.

After deployment, open the new tab as an administrator, choose a time, save, and generate the first report. Verify its timestamps, candle source, scenarios and token usage. Enabling daily generation does not enable hourly automation or live trading.

## Validation

Backend tests use an isolated test database, offline market data and mocked AI responses. Coverage includes complete-bar aggregation, UTC Monday weeks, stale/gapped data rejection, known-level validation, Tehran scheduling, daily deduplication, lock contention, failure handling, stored usage, admin-only writes and absence of entry-signal writes. Frontend tests cover stale reports, conditional scenarios, schedule controls and generation.
